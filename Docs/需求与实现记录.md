# ADB Quick Tool 需求与实现记录

## 记录规则

每项需求固定记录以下五项：

- 原始要求；
- 需求状态，使用“有效、已取消、已替代”；
- 实现位置，尚未实现时标记为“待实现”；
- 验证状态；
- 待实机项目，不涉及实机时标记为“无”。

详细技术方案、关键决策、开发流水账和阻塞信息记录到对应项目的 `Docs/PROJECT_MEMORY.md`，不在本文件重复记录。

### REQ-003：切换设备时同步更新设备管理数据

- 原始要求：点击切换其他设备后，文件浏览和应用列表需要随当前设备同步刷新，不能继续显示旧设备数据。
- 需求状态：有效。
- 实现位置：`src\Program.cs` 的设备选择变更处理、文件列表刷新和应用列表刷新逻辑。
- 验证状态：已完成代码实现，待正式程序实机切换设备验证。
- 待实机项目：在至少两台已连接设备之间切换，确认旧列表会先清空，再显示新设备的文件和应用。

### REQ-004：冻结设备切换不发起设备管理查询

- 原始要求：设备连接状态处于冻结状态时，点击切换设备不能使设备重新连接；应用列表和文件浏览内容均置空。
- 需求状态：有效。
- 实现位置：`src\Program.cs` 的 `OnSelectedDeviceChanged`、`RefreshSelectedDeviceDataAfterSelectionChange`。
- 验证状态：`build.ps1` 已编译通过并覆盖正式产物；静态回归检查确认冻结分支会先清空列表、取消刷新，防抖回调也会拒绝冻结设备。
- 待实机项目：选择 `freeze` 状态的设备，确认文件和应用列表为空，且没有发送文件/应用查询或触发连接恢复。

### REQ-005：删除设备必须确认 ADB 已断开

- 原始要求：删除设备无法彻底断开连接。
- 需求状态：有效。
- 实现位置：`src\Program.cs` 的 `DeleteSelectedDevice` 与 `IsDeviceListed`。
- 验证状态：`build.ps1` 已编译通过并覆盖正式产物；静态回归检查确认删除会禁止后台自动重连，且仅在断开成功、二次列表确认设备消失后删除设备行；失败路径保留设备行。
- 待实机项目：删除 TCP/IP 设备后，确认 `adb devices -l` 中不再包含该序列号；断开失败或仍存在时设备行必须保留。

### REQ-006：删除设备后应用稳定性

- 原始要求：出现闪退和卡顿 UI。
- 需求状态：有效。
- 实现位置：`src\Program.cs` 的 `AppendProcessResult`、`RunAdbShell`、`RunAdbShellCapture`、`RunAdbShellCaptureForDeviceProbe`。
- 验证状态：`build.ps1` 已编译通过并覆盖正式产物；静态回归检查确认空结果安全处理及三条已删除设备查询链路的重连/刷新抑制，正式程序启动后保持响应。
- 待实机项目：删除已连接设备并触发文件/应用/详情旧查询，确认程序不闪退、界面保持可操作，且不产生自动重连或重复刷新。
